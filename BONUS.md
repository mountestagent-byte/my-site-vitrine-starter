# Tu as fini en avance ?

Prends-les dans l'ordre. Chacun t'apprend quelque chose que les autres n'apprennent pas.

## 1. Fais parler ton CLAUDE.md

Demande à Claude Code :

```
Relis mon CLAUDE.md avec un œil critique. Qu'est-ce qui est trop vague pour
être suivi de façon fiable ? Réécris ces règles pour qu'elles soient vérifiables.
```

« Fais un site élégant » ne veut rien dire. « Padding vertical de 96px sur les sections »
se vérifie. C'est toute la différence entre un contexte décoratif et un contexte utile.

## 2. Le mode plan

```
/plan
```

Puis demande une évolution importante — une deuxième page, un formulaire de contact.
Claude te présente son plan avant de toucher au code. Tu valides, ou tu corriges le plan.
Sur un vrai projet, c'est ce qui évite les demi-heures perdues.

`Shift+Tab` fait défiler les modes de permission sans quitter la session.

## 3. Regarde ce que ça coûte

```
/context
```

Tu vois ce qui occupe la fenêtre de contexte : ton CLAUDE.md, les fichiers lus,
la conversation. C'est la meilleure façon de comprendre pourquoi un fichier de
600 lignes est une mauvaise idée.

Puis :

```
/compact
```

## 4. Une deuxième page

Ajoute une page `services.html` qui hérite du même design system.
Observe : tu n'as pas eu à redonner les couleurs. Elles étaient déjà dans le contexte.
